# AIMED AI 시스템 — 오픈소스 구성요소 검수 리스트

> **목적**: 외부(OpenAI) 공유 전, 자체 AI 시스템에 사용된 오픈소스(OSS) 구성요소를 실제 매니페스트 기준으로 확인·검수하여 ① 라이선스 적법성 검토 ② 자체 개발(proprietary) 부분과 OSS 토대의 명확한 구분 을 위한 자료.
> **검수 기준일**: 2026-05-26
> **검수 방법**: 추측이 아닌 실제 파일 확인 — `package.json`, `requirements.txt`, `*.csproj`, Unity `Packages/manifest.json`, 소스 `import` 구문 직접 검증 (검증 출처는 §6 참조)

**라이선스 분포(주요)**: MIT 다수 · Apache-2.0 다수 · BSD-3-Clause(torch/numpy 등) · **AGPL-3.0 1종(주의)** · **LGPL-3.0 1종(주의)**

### 핵심 검수 결론
1. 대부분 **MIT / Apache-2.0 / BSD** 계열로, 사내 사용 및 산출물(게임) 배포에 **법적 제약이 낮음**.
2. **주의 2건** 식별 — 외부 공유/상용 배포 전 검토 권장 (§2).
3. AIMED의 **자체 개발 영역**(에이전트 오케스트레이션 로직, ICS 계약 체계, 레벨 생성 알고리즘, 분류 체계 등)은 OSS가 아닌 **자사 IP**이며, 위 OSS는 그 토대 인프라일 뿐임 (§5).

## 5. 자체 개발(Proprietary) 영역 — OSS가 아닌 AIMED IP

> "오픈소스 위에서 무엇을 자체 구축했는가"의 구분. 외부 공유 시 **차별화 핵심**이자, 본 시스템이 단순 OSS 조합이 아님을 보여주는 부분.

| 영역 | 내용 | 토대 OSS |
|------|------|----------|
| 에이전트 오케스트레이션 | 11종 역할 분리 에이전트, Lead 조율, Phase Gate | Claude(API) 위 자체 설계 |
| **Integration Contract System(ICS)** | `_CONTRACTS.yaml`/`_ASSET_MANIFEST.yaml` 계약 추적 + Stage 5.5 통합 검증 | 전적 자체 설계 |
| 환각 방지 체계 | 4단 분류(Layer/Genre/Role/Tag), 5-Tier 검색, 6대 규칙, 차단형 훅 | 자체 설계 |
| Design Workflow(Stage 0~8) | 기획 파이프라인 + 신뢰도 점수/Expert 승격 | 자체 (db-client/score-manager 자작) |
| Virtual Player 의사결정 | P0~P5 우선순위 트리, 3-Tier 비전 폴백, 페르소나, 적응 학습 | OpenCV/YOLO 위 자체 로직 |
| **레벨 생성 알고리즘** | cowork 패턴 13종, 1:1 구조 보증, 공백 탐지 | NumPy 위 자체 알고리즘 |
| 레벨 생성 알고리즘 | cowork 패턴 13종, 공백 탐지, 1:1 구조 보증 | 자체 |
| ProjectHub MCP 브리지 | Unity 에디터 제어 프로토콜 | 의존성 0, 자체 구현 |
| Hermes 라우팅 데몬 | watcher→context→router→executor | pymongo 위 자체 구현 |
