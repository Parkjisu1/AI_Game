# NewPlay 개인 작업대·페르소나 변경본 R3 — 2026-09-22

**상태: 로컬 구현·검증 완료, 운영 Ubuntu 미적용.** 기존 운영 인수 ZIP을 대체하는 전체 백업이 아니라, 검토·적용 준비용 변경본입니다.

이 R3는 R2 결함 수정에 Git 코드 탐색·자동 갱신을 추가한 누적 변경본입니다. 이전 `newplay-workbench-persona-20260922-review.zip` 대신 `newplay-workbench-persona-20260922-r3.zip`을 검토하세요. 수정·시험 결과는 `REPORT.md`, 시험 준비 방법은 `QA-RUNBOOK.md`에 있습니다.

## 바뀐 사용 방법

1. NewPlay에서 **개인 작업대**를 엽니다. 기존 `/terminal` 주소를 그대로 사용합니다.
2. 프로젝트를 고르면 Git 주소·브랜치·커밋이 표시됩니다. 왼쪽에서 하위 폴더와 파일을 엽니다. 코드 강조·줄 번호·검색·실행 취소가 있는 편집기가 나타납니다.
3. 편집 후 **저장** 또는 **Ctrl+S**를 누릅니다. 아래 Git 변경 목록에서 저장된 내용과 HEAD를 비교합니다.
4. **터미널 연결**을 누르고 `claude`를 입력합니다. 기존과 같은 개인 Docker 작업 폴더와 실제 Claude Code를 사용합니다. 계정 인증은 본인이 합니다. 터미널에서 파일 생성·이동과 검사 명령도 실행할 수 있습니다.
5. **내 페르소나**에서 필수 메모와 상세 문서를 작성합니다. 자동 수집 기록은 후보로 표시되며, 필요한 내용을 초안에 가져와 수정합니다.
6. **초안 저장**은 상세 문서를 보관합니다. **본인 승인·적용**을 눌러야 상세 문서가 대리 작업에 사용됩니다. 관리자도 타인의 문서를 대신 승인할 수 없습니다.
7. 업무 내용을 넣고 **저장된 승인본으로 미리보기**를 누르면 이번 요청에 선택될 내용을 볼 수 있습니다.

저장 중에는 페르소나 입력을 잠시 잠급니다. 저장이 끝나면 다시 편집할 수 있습니다. 현재 페르소나 대리는 **저장소가 연결된 개발 작업대**에서 지원합니다. 기획·데이터·목업·저장소 없는 작업에서 대리를 요청하면 이유를 작업 카드에 남기고 중단합니다. 일반 맡기기는 기존대로 동작합니다.

## Git 코드 자동 확인

- **내 작업 코드**: 현재 개인 작업 폴더를 5초마다 확인합니다. 저장된 외부 변경은 자동 표시하며 미저장 초안은 보존합니다.
- **Git 최신 코드**: 원격 기본 HEAD를 읽기 전용으로 봅니다. 이 화면에서는 60초마다 fetch합니다. 수동 확인도 가능합니다. 개인 작업 파일에 자동 병합하지 않습니다.
- 기존 등록 프로젝트의 upstream 또는 origin을 사용합니다. 임의 Git URL 등록 기능은 이번에 추가하지 않았습니다. 저장소 접근 인증은 Claude 구독 인증과 별개입니다.
- 2,000개를 넘는 폴더 목록은 페이지로 이어서 봅니다. 인증·생성 파일, 링크·submodule은 제외하며 UTF-8 텍스트 최대 512 KiB를 지원합니다.
- 즉시 공동 편집 기능이 아닙니다. 원격에 push하지 않은 다른 사람의 개인 파일은 이 화면에 나타나지 않습니다.

## 분량 처리

- 필수 메모는 끝까지 전달합니다. 기존의 `저장 2,000자 / 전달 800자` 잘림을 제거했습니다.
- 상세 문서 원문은 최대 50,000자까지 저장합니다. 한도를 넘으면 명시적으로 거절하며 몰래 자르지 않습니다.
- 빈 줄·Markdown 제목으로 문단을 나누고, 업무의 단어·한글 두 글자 조합과 겹치는 문단 및 채택 사례를 우선 선택합니다. **의미 임베딩 검색이나 AI 요약은 아닙니다.** 추가 모델 호출은 없습니다.
- 동일 문단을 중복 전달하지 않습니다. 관련이 없거나 예산에 들어가지 않는 문단은 통째로 생략합니다.
- 기본 예산 6,000, 조정 범위 2,000~16,000. **UTF-8 바이트 길이에 기반한 보수적 토큰 추정 예산이며 실제 모델 토큰 수·과금량·컨텍스트 한도 보장은 아닙니다.** 나머지 시스템 지침·코드·도구 출력 토큰은 별도입니다.
- 필수 메모와 기본 안내만으로 예산을 넘으면 승인 또는 대리 실행을 중단하고 이유를 표시합니다.
- 실행 시 승인 원문을 임시 파일로 제공해 필요한 부분을 추가로 읽을 수 있게 합니다. 추가 읽기는 토큰을 더 사용합니다. 임시 파일은 실행 종료·실패 뒤 정리합니다.
- 화면 미리보기와 실행기는 동일한 JavaScript 선택기를 사용합니다. 실행기의 원문 파일 경로 길이에 따라 예측 분량이 조금 달라질 수 있습니다.
- 승인 이력은 최근 20개, 수집 후보는 최근 50개입니다. 기존 원본 Claude 전사 저장 경로는 바꾸지 않았습니다.

## 작업 파일과 권한

- 편집 대상은 로그인한 사람의 해당 프로젝트 worktree입니다. 사용자 이메일을 요청 본문에 넣어 다른 사람으로 바꿀 수 없습니다.
- 웹과 게이트웨이 사이 파일 요청에 서명·수명·일회용 식별자를 사용합니다. 브라우저에 내부 서명키를 내보내지 않습니다.
- 경로 이탈, 심볼릭 링크, 하드링크, 특수 파일, `.git`, `.env*`, 개인 인증 폴더를 편집 API에서 거절합니다.
- Git 비교도 검증한 일반 텍스트 파일의 내용으로만 수행합니다. 폴더 전체 비교와 링크를 거절하고, 삭제 파일 및 새 하위 폴더의 파일을 표시합니다.
- UTF-8 일반 파일, 최대 512 KiB를 지원합니다. 이 범위를 넘는 파일은 터미널에서 다룹니다.
- 저장 전 파일 해시를 비교합니다. 다른 창이나 CLI가 이미 바꿨다면 409로 거절하고 편집창 내용은 남깁니다. 협조하지 않는 CLI의 정확히 동시인 쓰기까지 트랜잭션으로 막는 구조는 아닙니다.
- 같은 사용자의 IDE 파일 요청은 게이트웨이에서 순서대로 처리합니다. 성공한 편집 저장은 해당 사용자·프로젝트의 학습용 세션으로 남깁니다.
- 기존 팀 공유 Git 저장소 구조는 유지됩니다. 터미널 사용자를 완전 격리하는 보안 경계가 새로 생긴 것은 아닙니다.
- 저장 전 파일 이동·프로젝트 전환·화면 링크 이동에는 확인을 둡니다. 브라우저 뒤로가기 등 모든 탐색을 완전히 통제하지 않으므로 이동 전 저장하세요.

## 현재 검증 범위와 남은 것

자세한 결과는 `REPORT.md`를 보세요. 실제 화면과 API·임시 Mongo·Linux 파일 처리 시험은 통과했습니다. 로컬 시험에서 Docker 준비와 터미널 PTY는 대체 장치를 사용했습니다.

운영 SSH 키가 만료되어 **운영 서버 적용, 실제 Docker 작업대에서 새 파일 API 검증, 실제 개인 계정 AI 작업, 품질 동등성 비교는 하지 않았습니다.** 계정 로그인만으로 모델·설정·도구·작업 맥락이 같아지는 것은 아닙니다. 대리 실행기의 모델 선택·fallback·CLI 버전 정책도 이번 변경 범위에 포함하지 않았습니다.

직접 터미널에서 로그인한 자격 증명과, 기존 맡기기·대리 실행기가 사용하는 개인 토큰 등록 경로는 별개입니다. 이번 변경이 양쪽의 인증 정보를 자동 동기화하지는 않습니다.

## 파일 구성

- `changes/deploy/`: 바뀐 24개 소스·설정 파일의 최종본.
- `patches/web.patch`, `watcher.patch`, `gateway.patch`: 이전 검수본 대비 패치.
- `manifest.json`: 변경 파일의 이전·이후 SHA-256. 텍스트 줄바꿈만 다른 사본도 대조할 수 있도록 LF 기준 해시를 함께 기록.
- `verify_update.py`: ZIP 파일과 적용 대상 기준본의 읽기 전용 검증 도구. **적용·재시작 기능은 없습니다.**
- `qa/`: 검증 코드·결과·화면 캡처. 실제 계정 자격 증명과 DB 백업은 포함하지 않습니다.
- `QA-RUNBOOK.md`: Windows/WSL 로컬 시험용 전체 소스 준비, 임시 서비스 실행, 빌드·회귀 시험 절차.

인수 서버에서 기준 확인:

```bash
python3 verify_update.py --deploy-dir /home/newplay/newplay-deploy
```

검사 통과 후 적용 시에는 현재 소스·의존성·이미지를 백업하고, 작업 중인 AI·터미널을 확인해야 합니다. 웹 패키지는 `npm ci`와 빌드를 완료한 뒤 반영하고, 게이트웨이는 새 Python 도우미가 이미지에 포함되도록 재빌드해야 합니다. 워처·학습기는 새 `persona_context.js`와 수정 Python을 함께 반영해야 합니다. Compose 명령은 기존 서버의 **`--env-file .env.compose`**를 사용합니다. `.env`와 개인 토큰은 이 변경본으로 덮어쓰지 않습니다.

기존 `newplay-operator-handoff-20260918-r2.zip`은 갱신하지 않았습니다. 새 변경본의 운영 실측이 끝난 다음 최종 전달본을 갱신해야 합니다.

R2의 프로필 저장·학습은 `(email, project)` 고유 인덱스를 보장합니다. 기존 DB에 중복 프로필이 있으면 인덱스 생성과 해당 처리를 중단합니다. 자동 병합·삭제는 하지 않습니다. 적용 전 중복 여부와 인덱스 생성 권한을 확인하고, 중복이 있으면 각 원문을 보존한 상태로 운영자가 검토해야 합니다. 인덱스는 코드 롤백만으로 삭제되지 않습니다.
