# NewPlay Git 코드 탐색·자동 갱신 R3 — 2026-09-22

**로컬 구현과 검증 완료. 운영 Ubuntu에는 적용하지 않았습니다.** 화면 예시는 별도의 오프라인 HTML이며, 실제 구현은 변경 소스 ZIP에 들어 있습니다.

## 사용자가 추가로 할 수 있는 일

1. 등록된 팀 프로젝트를 선택하면 Git 주소, 개인 브랜치, 커밋, 마지막 확인 시각을 봅니다. 워처의 로컬 미러 origin보다 실제 Git 호스트인 upstream을 우선합니다. 주소의 사용자 정보·비밀번호·쿼리는 화면에 보내지 않습니다.
2. 내 작업 폴더에서 하위 폴더를 열어 코드를 탐색·편집합니다. 한 폴더 2,000개를 넘으면 다음 목록으로 이어서 볼 수 있습니다.
3. 자동 확인을 켜면, 화면이 보이는 동안 5초마다 작업 파일과 목록을 확인합니다. 터미널·AI·다른 창이 저장한 변경을 확인하며 저장하지 않은 편집은 자동으로 덮어쓰지 않습니다.
4. ‘Git 최신 코드’를 선택하면 등록된 원격 저장소의 기본 HEAD를 가져와 읽기 전용으로 탐색합니다. 이 화면에서는 60초마다 원격 확인을 시도합니다. ‘Git 최신 확인’으로 수동 확인도 가능합니다.
5. 원격 코드는 전용 refs/newplay/ide 아래에 가져옵니다. 개인 브랜치·HEAD·인덱스·작업 파일을 checkout/reset/merge하지 않습니다. 파일 삭제·읽기 실패·원격 인증 실패는 안내하고 편집 중인 내용은 남깁니다.

‘실시간’은 즉시 push 전송이 아니라 위 주기의 자동 확인입니다. 네트워크와 처리 시간만큼 더 걸릴 수 있습니다. 다른 팀원의 미저장 편집은 보이지 않으며, 각 개인 worktree의 저장된 내용과 원격에 push된 코드는 구분됩니다.

## 인수자가 알아야 할 범위

- 기존에 등록된 팀 저장소가 대상입니다. 새 Git URL 등록 화면, 모든 원격 브랜치 선택, submodule 재귀 연결, 실시간 공동 편집은 추가하지 않았습니다. 기본 원격 HEAD만 조회합니다.
- Git 호스트에 접근 가능한 작업대 네트워크와 Git 인증이 필요합니다. Claude 구독 로그인과 Git 접근 권한은 별개입니다. 실제 GitHub/GitLab 개인 인증으로 원격 fetch를 이번에 검증하지 않았습니다.
- UTF-8 일반 텍스트 최대 512 KiB. 인증 파일·Git 내부 파일·생성 폴더·심볼릭 링크·submodule은 코드 탐색에서 제외합니다. 원격 단일 폴더의 Git 목록 자체가 512 KiB를 넘으면 오류 안내합니다. 큰 파일·바이너리는 터미널 등 별도 도구가 필요합니다.
- 목록과 열린 파일은 자동으로 확인하지만 파일 편집자의 동시 쓰기 전체를 트랜잭션으로 잠그지는 않습니다. CLI가 정확히 동시에 쓰는 기존 저장 경쟁 경계는 유지됩니다.
- Docker 준비와 PTY는 로컬 대체 장치를 사용했습니다. 실제 Ubuntu Docker·공개 HTTPS/WSS·팀원 계정·업무 완주·품질 동등성은 별도 운영 실측이 필요합니다. R2의 프로필·페르소나·운영 경계는 `REPORT-R2.md` 그대로 남습니다.
- R3 ZIP은 원래 운영 기준본 대비 누적 변경 24개와 패치·검증 자료입니다. 전체 복구 백업이 아닙니다. R2를 이미 적용한 사본에는 패치를 그대로 덧붙이지 말고 기준 검증 후 변경을 대조해야 합니다.
