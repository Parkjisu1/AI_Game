### R3-QA-01 — 파일 전환 중 새 입력 소실

재현: README.md를 열고 수정하지 않은 상태에서 다른 파일 app.ts를 클릭합니다. app.ts 읽기 응답을 잠시 지연한 동안 기존 README 편집기에 새 문장을 입력합니다. 응답을 풀면 app.ts로 바뀌면서 새 문장이 사라집니다. README 저장 파일에도 해당 문장이 없고, 재확인 창도 나오지 않습니다.

원인: `WorkbenchView.tsx:116`의 전환 확인은 요청을 보내기 전에만 실행합니다. `:119`는 응답 후 그 사이 생긴 편집 여부를 다시 확인하지 않고 `setFile`로 교체합니다. `:185`에서 편집기의 `readOnly`는 원격 보기 여부만 전달하므로 로딩 중에도 입력할 수 있습니다. `CodeEditor.tsx:23`도 이 값만으로 입력 가능 여부를 결정합니다.

영향은 **해당 로딩 구간에 새로 입력한 미저장 내용의 소실**입니다. 저장된 원본 파일을 손상시키는 문제로 확대하여 주장하지 않습니다.

권장 수정: 파일 전환·다시 열기 요청 중 편집을 잠그거나, 응답 적용 전에 요청 당시의 편집 버전과 현재 버전을 대조하여 새 입력을 보존합니다. 확인 위치: `browser-adversarial.py`, `browser-adversarial-results.json`의 첫 항목, `draft-before-read-response.png`, `draft-after-read-response.png`.

### R3-QA-02 — 원격 실패 안내가 캐시 조회로 해제

재현: 원격 조회가 한 번 성공해 캐시가 있는 상태를 만듭니다. 다음 60초 원격 fetch만 502로 실패시키면 오류 안내가 나타납니다. 5초 뒤 원격에 다시 접속하지 않고 기존 캐시를 조회하는 snapshot이 성공하면 오류 안내가 사라집니다. fetch 호출은 최초 성공과 실패를 합쳐 2회뿐입니다.

원인: `WorkbenchView.tsx:44`의 `applyListing`이 모든 목록 응답에 `setLive("")`를 실행합니다. `:85`의 원격 fetch는 60초 간격이고 `:88`의 캐시 snapshot은 5초 간격이므로 두 성공 상태가 혼동됩니다.

마지막 원격 성공 시각은 화면에 남습니다. 따라서 ‘모든 오래된 코드 표시를 숨긴다’는 주장은 하지 않습니다. 문제는 **재연결되지 않았는데 실패 안내가 사라진다**는 점입니다. 원격 성공 상태와 캐시 조회 상태를 분리하고, 원격 성공 시에만 원격 오류를 해제해야 합니다.

통신 실패는 브라우저에서 통제했고 실행 화면은 수정하지 않은 실제 R3 빌드입니다. 운영 Git 서버에 장애를 주입하지 않았습니다. 근거: 결과 JSON의 두 번째 항목, `remote-error-shown.png`, `remote-error-cleared-without-retry.png`.
