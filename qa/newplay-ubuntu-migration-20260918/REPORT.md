## Ubuntu 오류 팝업과 부팅 문제

팝업은 update-notifier의 ‘시스템 프로그램 오류를 발견했습니다’였습니다. `/var/crash`의 유일한 보고서는 16:16의 커널 패키지 설치 실패였습니다. 패키지 복구 후 `dpkg --audit`는 비었고, 보고서를 별도 보존한 다음 확인 처리하고 취소했습니다. 외부 오류 보고는 보내지 않았고 향후 오류 알림은 유지했습니다.

앞서 발생한 커널 패닉과 USB 인식 지연의 근본 원인은 확정하지 못했습니다. 6.8 커널도 설치했으나 정상 부팅이 확인된 상태가 아닙니다. 현재 7.0 커널에서 서비스가 돌아가는 것을 재부팅 안정성 확보로 해석하지 않습니다.

Mongo 8.3.11은 현재 커널에서 기본 실행을 거부했습니다. `GLIBC_TUNABLES=glibc.pthread.rseq=1`로 per-thread allocator 사용을 확인했고 1,000건 쓰기/조회 및 실제 복원을 통과했습니다. 측정된 우회 설정이며 커널의 공식 지원이나 장기 안정성을 증명하지는 않습니다.

## 검수 중 실패도 남깁니다

- 첫 외장 복사는 exFAT에서 `cp -a` 소유권 보존이 실패했습니다. 아카이브 파일을 일반 복사하고 해시를 대조하도록 수정했습니다. tar 내부 Linux 권한은 보존됩니다.
- 첫 Qdrant 복원 시험에서 파일 열기 한도를 빠뜨려 시작에 실패했습니다. 운영 Compose와 같은 65,536으로 맞춘 뒤 통과했습니다.
- SSH 중계 준비 중 잘못된 키 옵션으로 원격 접속을 막았습니다. 사용자가 보관본을 복구했고, 별도 임시 키를 사용해 검수를 마쳤습니다.
- 게이트웨이 재생성 때 `.env.compose` 지정 누락으로 Docker 그룹이 999로 바뀌었습니다. 실제 그룹 984를 명시한 설정으로 재생성 후 확인했습니다.
- Git 등록 부분 복원 시 새 상위 폴더가 root 소유가 되어 터미널 생성이 실패했습니다. 해당 상위 폴더 소유자를 1000:1000으로 복원하고 재검사했습니다.
- 초기 브라우저 시험기의 쿠키 전달·SSE 대기·쉘 준비 시점 문제가 있었습니다. 실제 스트림을 전달하는 로컬 시험 중계와 준비 대기로 고친 뒤 최종 통과했습니다.

## 백업과 전달물

최신 검증 백업은 `/data/newplay-backups/20260918T180601` 및 외장하드 `Expansion/NewPlay-native-backups/20260918T180601`입니다. 18:08:04 백업 완료 후 별도 복원 검사가 통과했습니다. 일일 백업은 오전 04:30, 서비스 잠시 정지 후 재기동 방식이며 개인 작업대나 AI 작업이 실행 중이면 보류합니다. 자동 보관본 삭제는 하지 않습니다.

`newplay-hub-native-ubuntu-20260918-review.zip`은 **개발자 검토용**입니다. 실제 서버 웹·워처 소스, 게이트웨이, Docker 구성, 비밀 값 없는 설정 양식, PowerShell 도구, 회귀 검사, 운영 설명을 담았습니다. 각 파일 해시는 `SHA256SUMS`에 있습니다. 운영 DB·실제 비밀 설정·개인 토큰은 이 ZIP에 넣지 않았습니다. 운영 인수자는 별도의 전체 백업도 받아야 합니다.
