# NewPlay 완료 여부 재검수 — 2026-09-21

**판정: 전달 행위를 제외해도 전수 완료가 아닙니다.** 기존 기능/복구 검수의 통과 기록은 있으나, 실제 팀 접속 경로는 이번 재측정에서도 통과하지 않았습니다. 현재 운영 서버 내부 재검수는 SSH 인증 거부로 미완료입니다. 코드를 수정하거나 서비스를 재기동하지 않았습니다.

## 9월 21일 직접 확인

- 검사 PC의 Tailscale은 Running이고, 새 Ubuntu 등록 기기 `newplay-1.tailf6f809.ts.net` / `100.72.201.90`은 Offline, 마지막 관측은 9월 18일 16:46:50 KST입니다. 이것만으로 Ubuntu 자체가 정지했다고 해석하지 않습니다.

## 이어서 확인할 순서

1. 유효한 운영 SSH 접근을 확인하거나 검수용 접근을 다시 마련합니다. 후속 확인에서 서버가 비밀번호 인증을 허용하는 것을 확인했습니다. 현재 Windows PC의 SSH 창에서 본인이 Ubuntu `newplay` 암호를 입력하면 원격으로 검수 키를 등록할 수 있으므로 현장 방문이 필수는 아닙니다. `Open-NewPlay-QA.ps1`은 해당 창을 열고 인증 성공 후 4시간짜리 키 등록과 Ubuntu 셸을 실행합니다. 비밀번호는 채팅이나 검사 로그에 받지 않습니다. 현재 암호 로그인 성공 자체는 아직 확인하지 않았습니다.
2. 준비한 읽기 전용 검사로 현재 커밋·8개 서비스·DB/작업 상태·최근 백업·디스크·부팅 기록·임시 권한 정리를 측정합니다. 완료 표시만으로 최근 백업의 해시 검사를 대신하지 않습니다.
3. Tailscale 등록 응답과 팀 이름/프록시 경로 문제를 해결한 뒤 실제 팀 주소 HTTPS/WSS를 검수합니다. 필요한 서비스 계정 승인은 계정 관리자/인수자 본인이 합니다.
4. 현장 화면을 볼 수 있는 상태에서 HP의 정상 종료·재부팅·USB를 검수합니다. 데이터 복구 VM 재부팅으로 대체하지 않습니다.
5. 사용할 외부 기능 및 실제 Google/Claude 작업은 해당 계정 소유자와 확인합니다.

현재의 정확한 상태는 **기존 내부 기능·복구 시험 통과 / 팀 접속 실패 / 현재 내부 운영 재검수 미완료**입니다. ‘전달만 하면 끝’이라는 판정은 근거가 없습니다.
