## 아직 실행하지 못한 것과 이유

현재 서버 `newplay@172.31.29.251`의 검수용 SSH가 반복해서 `Permission denied (publickey,password)`로 거절됐다. 오늘 운영 상태, 팀 Git 구성, Tailscale/Serve, 수정 이후 백업의 수집·전체 복구를 실제로 실행할 수 없었다. 비밀번호 수집·다른 계정 토큰 재사용·접속 우회는 하지 않았다.

기존 복구 VM도 해당 운영 Ubuntu에 만들어져 있으므로 지금 접근할 수 없다. 현재 Windows의 WSL에는 Docker/QEMU 실행기가 없어 이 턴에서 전체 운영 복구 시험을 수행하지 않았다. 대신 실행 가능한 소스 재구성·빌드·회귀 시험을 완료했다.

인수자의 Google·Claude·Git·서비스 관리자 인증/승인은 본인과 기존 관리자가 수행해야 한다. HP 물리 재부팅은 현장 접근 및 복구 경로 확인 뒤 진행해야 하며 이번에 원격 재부팅하지 않았다.

## 이어서 진행할 준비

이 폴더의 `Open-NewPlay-Connection.cmd`는 기존 검수 접속 도구를 새 작업명으로 준비한 것이다. 사용자가 직접 실행하면 SSH 창에서 Ubuntu 암호를 직접 입력한다. 채팅에 암호를 보내지 않는다. 지정된 현재 PC IP 제한과 4시간 만료를 유지하며 sudo 권한은 추가하지 않는다. 이번에 이 연결 갱신 자체를 완료했다고 기록하지 않는다.

접속 갱신 후: 현재 버전/건강 확인 → 기존 접속 장애 점검 → 소유자 인증 후 실제 팀 Git/HTTPS/WSS 검수 → 수정 이후 백업 확보 및 별도 환경 전체 복구 → 전달본의 데이터 기준 갱신. 권한 이양과 실제 개인 계정 업무는 `ACCEPTANCE.md`의 담당자별 확인으로 닫는다.
