운영자 r2 ZIP의 `02-native-backup/20260924T043003`이 기준입니다. 개인 작업대·페르소나·Git 기능과 9/23 UI 수정이 반영된 **9/24 04:30 백업**입니다. 이전 9/18 백업과 R3 패치를 조합할 필요가 없습니다.

## 순서

1. 별도 Ubuntu와 Docker를 준비합니다. 복구 시험에서는 외부 통신을 차단해 작업기의 중복 외부 요청을 방지합니다. 인수자 본인 접근을 확보합니다.
2. 백업 폴더에서 `sha256sum -c SHA256SUMS`와 `COMPLETE`를 확인합니다.
3. 빈 점검 폴더에 `sudo tar --zstd --numeric-owner -xpf native-state.tar.zst -C 점검폴더`로 먼저 풉니다. Linux 소유권·권한·링크를 유지합니다.
4. `zstd -dc docker-images.tar.zst | docker image load`로 포함 이미지를 읽습니다. 임의의 최신 이미지로 바꾸지 않습니다.
5. 새 대상의 `/home/newplay/newplay-deploy`, `/home/newplay/preview-build.sh`, `/data/newplay`를 복원합니다. 기존 데이터가 있다면 자동 삭제하지 않고 별도 보존합니다. 백업에 웹 `.next`, 의존성, Git 이력과 실제 설정이 포함되어 있어 소스 재빌드·패치 재적용은 필요하지 않습니다.
6. 호스트 UID/GID·Docker 그룹 번호를 `.env.compose`와 대조합니다. 시험은 UID/GID 1000을 유지하고 Docker 그룹 번호만 VM에 맞췄습니다. 실제 `.env.web`·`.env.watcher`를 예제로 덮어쓰지 않습니다.
7. 배포 폴더에서 `docker compose --env-file .env.compose config --quiet`를 확인합니다. Mongo·Qdrant·Ollama를 먼저 기동해 데이터를 확인한 뒤 나머지를 기동합니다. DB 원본 볼륨과 논리 백업을 같은 데이터에 중복 복원하지 않습니다.
8. `docker compose --env-file .env.compose up -d --no-build --pull never`로 포함 버전을 실행합니다. 서비스 8개·health·접근 차단·터미널·파일·프로필·검색을 검수합니다.
9. 실제 Google·Claude·Git 인증과 HTTPS/WSS를 인수자 본인 계정으로 확인한 뒤 트래픽을 전환합니다.
10. 백업 스크립트·서비스·타이머와 실제 외장하드 마운트를 확인하고 예약 백업을 활성화합니다. 시험 VM에서는 타이머를 끄고 원본 백업을 읽기 전용으로 연결했습니다.
