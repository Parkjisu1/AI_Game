## 전체 복구와 실제 기능

운영 서버 안에 이미 준비된 Ubuntu 복구 시험 디스크를 변경하지 않고 새 qcow2 overlay를 만들었다. VM은 별도 QEMU 프로세스이며 외부 통신을 차단했다. 원본 외장 백업은 읽기 전용 9p로 연결했다. 가상화 접근은 기존 사용자 권한을 사용했고 호스트에 관리자 권한을 추가하지 않았다.

시험 VM에서 이전 시험 데이터를 별도 폴더에 보존한 뒤 오늘 백업의 이미지와 전체 상태를 복원했다. 최신 웹/워처 커밋을 확인했으며 소스를 새로 빌드하거나 과거 패치를 추가 적용하지 않고 복원된 실행 산출물을 사용했다. UID/GID 1000을 유지하고 Docker 그룹 번호만 시험 VM의 988로 맞췄다.

## 남은 인수 조건

- **팀 Git:** `github-webstore` 별칭 미해결, 실제 팀 원격 조회 실패. 복구 환경에서도 502를 정상 오류 안내로 확인했다. 올바른 작업대 SSH/원격 구성과 저장소 소유자가 승인한 본인 인증이 필요하다. 합성/로컬 Git 성공을 실제 팀 Git 성공으로 표시하지 않는다.
- **팀 접속:** Tailscale `NeedsLogin`, Serve 설정 없음. 계정 관리자의 기기 승인 후 실제 HTTPS/WSS 경로 구성이 필요하다.
- **본인 권한/업무:** Ubuntu·NewPlay·Git·OAuth·Tailscale 인수자 권한과 Google/Claude 실계정 작업, 본인 배포/되돌리기 검수.
- **HP 물리 재부팅:** 이번 검증은 VM 재부팅이며 HP의 BIOS/USB/커널 안정성 검증은 아니다.
- **품질/선택 기능:** 직접 CLI와 동일 품질, 사람의 능력 복제, 선택 외부 기능 전체의 실계정 검증을 완료했다는 판정은 하지 않는다.

오늘 가능한 기술 기반 작업과 최신 복구 자료 준비는 완료했지만, 위 항목이 남아 있으므로 **최종 권한 이양 완료**로 판정하지 않는다.
