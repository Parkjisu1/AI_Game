# Beat Chart 작성 방법론 — 퍼즐 장르 공용

> 패키지(PKG) 단위로 레벨 페이싱을 설계하는 표준 방법론.
> 디렉터가 작성, AI는 이 디렉션에 맞춰 Level Library를 생성.
> 출처: BalloonFlow_BeatChart_Direction (2026-04-29 검증된 패턴) → 장르 일반화

---

## 0. 적용 대상
- 모든 퍼즐 sub_genre (queue_sort, block_slide, screw_remove, match3, merge)
- "PKG 단위로 패키지를 묶어 출시"하는 콘텐츠 구조에 공통 적용
- BalloonFlow는 `300레벨 / 15PKG / 20레벨 per PKG` 사례

---

## 1. 입력 정보 (디렉터가 채워야 하는 칸)

### 1-1. 전체 구조
```yaml
project: <프로젝트명>
core_mechanic: <한 문장 요약 — 유저가 반복하는 핵심 행위>
total_levels: <총 레벨 수>
package_count: <패키지 수>
levels_per_package: <패키지당 레벨 수>
fail_condition: <실패 조건 정의>
clear_condition: <클리어 조건 정의>
```

### 1-2. 레벨 설계 Hard Rules (위반 절대 불가)
프로젝트마다 값을 채우되, 항목은 공통:

| 항목 | 의미 | 예시 (BalloonFlow) |
|---|---|---|
| color_count_per_level | 한 레벨 동시 색상 수 범위 | 2~11종 |
| board_size_range | 보드 셀 수 범위 (min~max) | 200~2,000셀 |
| gimmick_max_per_level | 레벨당 동시 기믹 종류 상한 | 5종 |
| input_unit_max | 핵심 입력 단위 한도 (큐/홀더 등) | 큐 가로 2~5칸 |
| capacity_max_table | 자원 그룹별 최대치 표 | 허용량별 탄창 max |

### 1-3. 레벨 설계 Soft Rules (예외 허용하되 최소화)
| 규칙 | 목적 |
|---|---|
| 동일 기믹 N레벨 이상 연속 등장 금지 | 단조로움 방지. BalloonFlow는 N=6 |
| 기믹 사용 후 M레벨 이내 재등장 | 망각 방지. BalloonFlow는 M=30 |
| 동일 파라미터 K레벨 이상 연속 동일값 금지 | 변화 유지. BalloonFlow는 K=4 |

## 2. PKG 단위 디렉션 테이블

각 PKG마다 아래 항목을 채움. 표 형식 권장.

### 2-1. PKG 의도
- 한 줄로 요약: "코어 학습", "기믹 확장", "조합 마스터리" 등

### 2-2. 난이도 구성 (purpose_type 분포)
```yaml
package_N:
  tutorial: <개수>      # 메카닉/기믹 학습. 색상 2~3종, 가이드 제공
  normal: <개수>        # 일반 플레이. 적절한 고민
  hard: <개수>          # 도전. 순서 전략 핵심
  super_hard: <개수>    # 패키지 보스. 과금 포인트
  rest: <개수>          # 하드 직후 긴장 해소. 색상 3~4종
```

### 2-3. 패키지 내 포지션 규칙 (필수 준수)

```
pos 1 또는 11  → 기믹 도입 시 튜토리얼 (해당 PKG에 신규 기믹이 있을 때만)
pos 4, 9, 14, 19 → 하드 또는 슈퍼하드
pos 5, 10, 15, 20 → 휴식 (하드 직후 배치)
나머지         → 노말
```

> PKG 1 예외: 학습 구간이라 pos 19에만 하드, pos 20에 휴식. 나머지 튜토리얼+노말.
> 슈퍼하드: PKG 2부터 pos 19가 슈퍼하드. PKG 1은 일반 하드.

### 2-4. 목표 지표
```yaml
target_clear_rate:  # 최적 봇 시뮬 기준
  min: <%>
  avg: <%>
  max: <%>
target_attempts:
  min: <회>
  avg: <회>
  max: <회>
```

### 2-5. 색상 수 분포
```yaml
color_count:
  min: <종>
  avg: <종>
  max: <종>
distribution:  # 색상 N종이 차지하는 비율 (선택)
  "2": 5%
  "3": 20%
  ...
```

### 2-6. 보드 사이즈
```yaml
board_cells:
  avg: <셀>
  median: <셀>
  min: <셀>
  max: <셀>
```

### 2-7. 기믹 수
```yaml
gimmick_count:  # 레벨당 기믹 종류 수
  min: 0
  avg: <>
  max: 5
zero_gimmick_ratio: <%>  # 기믹 0종 레벨 비율
package_gimmicks:  # 이 PKG에 등장하는 기믹 목록
  - name: <기믹명>
    intro_level: <도입 레벨>
    frequency: <도입 PKG N회 / 이후 M회>
```

### 2-8. 신규 요소 도입
```yaml
new_colors: [<레벨>]   # 신규 색상 도입 레벨
new_gimmicks: [<기믹명: <도입 레벨>>]
```

### 2-9. 과금 포인트
- 어느 pos가 과금 트리거인지 (보통 pos 19 슈퍼하드)
- 첫 실패 예상 레벨

## 3. 톱니(Sawtooth) 난이도 리듬

```
난이도 ─┐                ┌─┐                ┌─┐
        │ ╱╲             │ │ ╱╲             │ │
       ╱╲  ╲╱╲         ╱╲│ │╱  ╲╱╲         ╱╲│ │
      ╱  ╲    ╲       ╱   ╲╱     ╲        ╱   ╲╱
     ╱    ╲    ╲╲    ╱             ╲     ╱
   tutorial │  hard   │   normal   │  hard │  rest
   pos1     pos4      pos5         pos9    pos10
```

- 노말로 서서히 올라감 → 하드/슈퍼하드에서 정점 → 휴식에서 급격히 해소 → 반복
- **난이도 순서 (어려운 순)**: 슈퍼하드 > 하드 > 노말 > 휴식 > 튜토리얼
- 모든 지표(CR, 시도횟수, 오브젝트 수, 기믹 수)에서 이 순서 유지 — 위반 절대 불가

---

## 4. 색상 계층 규칙 (purpose_type별)

```
튜토리얼 ≤ 휴식 ≤ 노말 ≤ 하드 ≤ 슈퍼하드 (색상 수)
```

| purpose_type | 색상 수 | 근거 |
|---|---|---|
| 튜토리얼 | 해당 PKG min, 최대 5종 | 기믹 학습에 집중 |
| 휴식 | min ~ REST_MAX (PKG 단계별 점증) | 긴장 해소. 색상 부담 최소 |
| 노말 | 자연 분포 (강제 floor 없음) | 베이스라인 |
| 하드 | ceil(노말avg)+1 ~ 슈하min-1 | 노말보다 확실히 높게 |
| 슈퍼하드 (PKG 보스) | 해당 PKG max | 최대 부담 |

### 금지 규칙
- 같은 PKG 내에서 휴식 N색 + 노말 (N-1)색 공존 금지
- 같은 PKG 내에서 노말이 하드보다 높은 색상 지양

### 신규 요소 도입 시 균형
- **신규 색상/기믹 도입 레벨에서는 다른 축을 줄임** (예: 색상 신규 → 기믹 0종 또는 오브젝트 수 직전 대비 감소)
- 복잡도 증가와 물량 증가를 동시에 주지 않음

---

## 5. 기믹 도입 원칙

### 5-1. 기믹 격리 (Hard Rule)
- 도입 레벨에서는 **해당 신규 기믹만** 등장. 기존 기믹 미등장
- 도입 후 2~3레벨은 해당 기믹만 사용 (적응 구간)
- 이후 기존 기믹과 혼합 허용

### 5-2. 기믹 도입 간격 (커브 패턴)
```
초반 PKG: +10레벨 간격 (빠른 학습)
중반 PKG: +20레벨 간격 (조합 심화)
후반 PKG: +40레벨 간격 (완숙 + 마지막 기믹)
신규 없는 PKG: 기존 기믹 조합 심화 구간 (예: PKG 3, 10, 12, 14)
```

### 5-3. 기믹 빈도 (PF 패턴 기반)
- **기본 양념 기믹**: 도입 후 전 PKG에 걸쳐 5~17회 (꾸준한 등장)
- **일반 기믹**: 도입 PKG에서 3~5회 집중 → 이후 1~3회 (망각 방지)
- **희소 기믹**: 도입 후 0~2회 (등장만으로 긴장감)
- **마지막 기믹**: 도입 PKG에서만 (학습 구간)

### 5-4. purpose_type별 기믹 종수 제한
| purpose_type | 허용 기믹 종 |
|---|---|
| 튜토리얼 | 1종 (도입 기믹만) |
| 휴식 | 0~1종 (가장 가벼운 것만) |
| 노말 | 2종 이하 권장 |
| 하드 | 2~3종 |
| 슈퍼하드 | 3~5종 (전체 혼합 가능) |

## 6. 입력 단위 (큐/홀더/스왑존 등) 운용 규칙

> sub_genre별로 "유저가 즉시 다룰 수 있는 입력 자원"의 형태가 다름. 공통 패턴:

- **튜토리얼/도입 레벨에서는 입력 단위를 좁힘** — 신규 기믹 학습에 집중
- **PKG 진행에 따라 평균 단위 폭을 점진 확장**
- **하드/슈퍼하드는 노말보다 입력 단위가 넓음** (자원 관리 복잡도 증가)
- **휴식은 좁게** (긴장 해소)
- **동일 단위를 4레벨 이상 연속 사용 금지** (Soft Rule)

BalloonFlow 사례: 큐 가로 2~5칸 / 평균 PKG 1=3.0칸 → PKG 10~15=4.0~4.2칸

---

## 7. 자원 단위 운용 규칙 (탄창/무브/시간 등)

### BalloonFlow 사례: 레일 허용량 4단계 (40/80/120/160)
```
레벨 1~4: 허용량 학습 (40, 80, 120, 160 순서 고정)
PKG 1 나머지: 160 위주 + 40/80/120 환기
PKG 2+: 40:80:120:160 = 10:10:10:70 비율
160 연속 등장 제한: 3~4회 연속 시 다음은 반드시 환기
```

→ **장르 패턴**: 자원 한도가 여러 단계로 나뉘면 (1) 학습 구간에서 점진 도입, (2) 안정화 후 한 단계가 주력 + 나머지 환기.

## 8. 난이도별 UI 차별화 (선택 사항)
- 레벨 난이도(purpose_type)에 따라 플레이씬 UI 색상 변경
- HUD 프레임/테두리, 레벨 번호 뱃지, 세팅 팝업 등이 변경 범위
- 노말=기본, 하드=경고감 톤, 슈퍼하드=긴장감 톤
- 목적: 레벨 시작 전 난이도 즉시 인지 → 부스터 선제 사용 유도 → 과금 포인트 강화

## 9. 검증 워크플로우

```
레벨 생성 → 정적 검증 (난이도 점수)
              ↓ 범위 내
            동적 검증 (봇 시뮬레이션 — bot_simulation_spec.md 참조)
              ↓
            클리어율 목표 범위?
              YES → 확정
              NO  → 재생성 or 파라미터 조정
```

상세는 `methodologies/bot_simulation_spec.md` 참조.

## 10. AI 지시사항 (Beat Chart 작성 시 필수 준수)

1. **포지션 규칙 (필수)**: 위 §2-3 그대로
2. **난이도 순서 (필수)**: 슈퍼하드 > 하드 > 노말 > 휴식 > 튜토리얼 — 모든 지표
3. **기믹 격리 (필수)**: 도입 레벨에서 신규 기믹 단독 등장
4. **신규 요소 도입 시 다른 축 감소**: 색상/기믹/오브젝트 중 하나만 증가
5. **purpose_type별 색상/기믹 가이드 준수**
6. **각 레벨에 emotion_curve와 designer_note 필수 작성**
7. **Hard Rule 위반 절대 불가, Soft Rule 위반은 전체 레벨의 5% 이내**
