# 교차 검증 체크리스트 템플릿 — 퍼즐 장르 공용

> 문서 간 일관성을 추적하는 표준 양식.
> 값이 변경되면 이 체크리스트의 "관련 문서"를 전부 확인하고 동시 업데이트.
> AI에게 "이 체크리스트 기준으로 교차 검증해줘"라고 지시하면 자동 검증 가능.
> 출처: BalloonFlow_교차검증_체크리스트 (17개 항목, 30+ 변경 이력) → 장르 일반화

---

## 1. 작성 원칙

### 1-1. 항목 단위
- 한 줄로 정의 가능한 **확정값**을 하나의 항목으로 묶음
- "라이프 시스템", "광고 정책", "부스터 가격표" 등 **독립적으로 변경 가능한 단위**
- 항목 1개당 하위 표 1개 + 관련 문서 list

### 1-2. 항목 양식

```markdown
## N. <항목명>

| 항목 | 확정값 |
|------|-------|
| <세부 1> | <값> |
| <세부 2> | <값> |

관련 문서:
- [ ] <문서 A> (§<섹션>)
- [ ] <문서 B> (§<섹션>)
- [ ] <데이터 시트> (<컬럼>)
```

### 1-3. 변경 이력 (문서 말미)
```markdown
| 날짜 | 변경 항목 | 이전 → 이후 | 영향 문서 수 |
|------|---------|------------|------------|
| 2026-04-03 | <항목> | <전> → <후> | <N>개 |
```

## 2. 퍼즐 장르 표준 항목 (15가지 — 프로젝트마다 채움)

아래 15개는 모든 퍼즐 프로젝트가 다뤄야 하는 **표준 검증 영역**. 항목 추가 가능, 누락 금지 권장.

### 2-1. 자원 한도 (예: 레일 허용량, 무브 수)
관련 문서: 코어메카닉_명세 / Beat Chart / 큐생성기_명세 / LevelDesign 시트 / 기믹 명세

### 2-2. 입력 단위 한도 (예: 탄창 max, 스왑 거리)
관련 문서: 코어메카닉_명세 / 큐생성기_명세 / Beat Chart / LevelDesign 시트

### 2-3. 부스터 종류 + 해금 + 가격
관련 문서: 아웃게임 디렉션 / 인게임아이템_UX명세 / 기믹 명세 (부스터 상호작용) / Beat Chart (해금 레벨) / 팝업텍스트 / 텍스트관리구조 / UX 플로우 / 피드백 디렉션

### 2-4. 이어하기 (컨티뉴) 정책
관련 문서: 코어메카닉_명세 / 아웃게임 디렉션 / UX 플로우 / 팝업텍스트 / 피드백 디렉션

### 2-5. 라이프 (하트) 시스템
관련 문서: 아웃게임 디렉션 / UX 플로우 (FTUE, 하트 0 플로우) / 팝업텍스트

### 2-6. 상점 상품 (코인, 번들, 광고제거 등)
관련 문서: 아웃게임 디렉션 / 팝업텍스트 / UX 플로우

### 2-7. 광고 정책 (전면, 보상형, FTUE 보호)
관련 문서: 아웃게임 디렉션 / UX 플로우

### 2-8. 스페셜 오퍼 (해금, 쿨타임, 노출 조건)
관련 문서: UX 플로우 / 아웃게임 디렉션

### 2-9. 용어 통일 (영문 명칭, 약어, 대소문자)
관련 문서: **전체 문서**

### 2-10. 기믹 도입 레벨
관련 문서: 기믹 명세 / Beat Chart / LevelDesign 시트

### 2-11. 자원 회전 속도 / 시간 압박
관련 문서: 코어메카닉_명세

### 2-12. 텍스트 관리 (언어, 이미지 텍스트, 로컬라이제이션)
관련 문서: 팝업텍스트 / 텍스트관리구조

### 2-13. 실패 후 플로우 (팝업 시퀀스)
관련 문서: UX 플로우 / 팝업텍스트 / 아웃게임 디렉션 / 피드백 디렉션

### 2-14. 클리어 후 플로우
관련 문서: UX 플로우 / 팝업텍스트

### 2-15. 밸런스 검증 기준 (목표 클리어율, 점수 밴드)
관련 문서: Beat Chart / 봇 시뮬레이션 명세 / 큐생성기 명세 / LevelDesign 시트

### 2-16. 난이도별 UI 표시 + 보상
관련 문서: UX 플로우 / 팝업텍스트 / 아웃게임 디렉션

### 2-17. PKG/난이도별 색상 분포 규칙
관련 문서: Beat Chart / LevelDesign 시트

## 3. AI 검증 지시 양식

### 검증 명령
```
"이 체크리스트의 §<번호> 항목에 대해,
관련 문서 전부에서 해당 값을 찾아서 일치하는지 확인해줘.
불일치하면 어떤 문서의 어떤 줄이 다른지 알려줘."
```

### 값 변경 워크플로우
```
1. 값 변경 결정
2. 이 체크리스트에서 해당 항목의 "관련 문서" 확인
3. 관련 문서 전부 동시 업데이트
4. 업데이트 후 교차 검증 재실행
5. 변경 이력 표에 행 추가
```

## 4. 자동 검증 통합 (Design Validator)

`design-validator.md` 에이전트의 Stage 3 검증에서 이 체크리스트를 입력으로 사용:

```yaml
input:
  checklist: cross_validation_template.md
  target_files: [<프로젝트의 관련 문서 모두>]
output:
  pass: <항목별 일치 여부>
  conflicts: 
    - item: <§N 항목>
      file_a: <파일:라인>
      value_a: <값>
      file_b: <파일:라인>
      value_b: <값>
```

---

## 5. AI 지시사항

1. **새 프로젝트 시작 시**: 위 17개 표준 항목을 모두 작성 (값 미정이면 TBD로)
2. **항목 추가 가능**: 프로젝트 고유 항목은 자유 추가, 단 관련 문서 list 필수
3. **변경 시 이력 작성 필수**: 날짜, 항목, 이전→이후, 영향 문서 수
4. **관련 문서 list 누락 금지**: 한 곳만 적은 항목은 교차 검증 의미 없음
5. **AI 자동 검증 결과는 conflicts 발견 시 즉시 디렉터에 보고**
